# ระบบรับของสาขา · MEGA Clinic

เว็บแอปสำหรับให้พนักงานหน้าสาขาบันทึกการรับสินค้า และให้ฝ่ายจัดซื้อดูรายการรับของของทุกสาขาได้ในที่เดียว ใช้งานบนมือถือได้

- หน้าเว็บ: GitHub Pages (ฟรี)
- ระบบล็อกอิน ฐานข้อมูล และที่เก็บรูป: [Supabase](https://supabase.com) (แพ็กเกจฟรีเพียงพอสำหรับเริ่มต้น)

## ความสามารถ

| หน้า | ใครใช้ | ทำอะไรได้ |
|---|---|---|
| กรอกข้อมูลครั้งแรก | ผู้ใช้ใหม่ | ชื่อ นามสกุล ชื่อเล่น สาขาประจำ และบทบาทที่ต้องการ (บทบาทอื่นนอกจากพนักงานสาขาต้องรอผู้ดูแลระบบอนุมัติ) |
| บันทึกรับของ | ทุกคน | พิมพ์รายการสินค้า ใส่จำนวนและหน่วย เลือกสาขา วันที่รับ แนบรูปสินค้า (1–6 รูป) เลือกเอกสาร (ใบกำกับภาษี / ใบส่งของ / ไม่มีเอกสาร) แนบไฟล์เอกสาร และใส่หมายเหตุ ชื่อผู้รับดึงจากบัญชีที่ล็อกอินอัตโนมัติ |
| สรุปการรับของ | ทุกคน | แสดงเลขที่ GR และสรุปรายการหลังกดยืนยัน |
| รายการของฉัน | ทุกคน | เห็นเฉพาะรายการที่ตัวเองเป็นผู้รับ |
| รายการสาขา | ทุกคน | เห็นทุกรายการของสาขาประจำ และกด "ขอดูสาขาอื่น" เพื่อส่งคำขอให้ผู้ดูแลระบบอนุมัติ |
| รายการทุกสาขา | จัดซื้อ / ผู้ดูแลระบบ | กรองตามสาขา ช่วงวันที่ เอกสาร สถานะ ค้นหา ดูรายละเอียดและรูป กด "ตรวจสอบแล้ว" และส่งออก Excel (CSV) |
| จัดการสิทธิ์ | ผู้ดูแลระบบ | กำหนดบทบาท ขอบเขตการดู (ของตัวเอง / สาขาที่เลือก / ทุกสาขา) และสิทธิ์รายข้อ พร้อมประวัติการเปลี่ยนสิทธิ์ |

### บทบาทเริ่มต้น

| บทบาท | ขอบเขตการดู | ส่งออก | ตรวจสอบ | จัดการสิทธิ์ |
|---|---|---|---|---|
| พนักงานสาขา | ทุกรายการของสาขาประจำ | – | – | – |
| หัวหน้าสาขา | ทุกรายการของสาขาประจำ | ✓ | – | – |
| จัดซื้อ | ทุกสาขา | ✓ | ✓ | – |
| ผู้ดูแลระบบ | ทุกสาขา | ✓ | ✓ | ✓ |

ผู้ใช้ไม่ต้องสมัครสมาชิก เข้าสู่ระบบครั้งแรกด้วยบัญชีบริษัทแล้วกรอกข้อมูล 1 หน้า ระบบจะสร้างบัญชีให้เอง บทบาทที่เลือกเป็นเพียง "คำขอ" สิทธิ์จริงเปลี่ยนได้โดยผู้ดูแลระบบเท่านั้น

พนักงานสาขาและหัวหน้าสาขาเลือกเองได้ตอนกรอกข้อมูลครั้งแรก ไม่ต้องอนุมัติ ส่วนจัดซื้อและผู้ดูแลระบบต้องรออนุมัติ การดูรายการของสาขาอื่นต้องส่งคำขอ และผู้ดูแลระบบอนุมัติรายสาขา

สิทธิ์ทั้งหมดบังคับที่ฐานข้อมูล (Row Level Security) ไม่ใช่แค่ซ่อนปุ่มในหน้าเว็บ แม้มีคนแก้โค้ดหน้าเว็บก็ดึงข้อมูลที่ไม่มีสิทธิ์ไม่ได้

## ลองดูก่อน (โหมดตัวอย่าง)

ถ้ายังไม่ได้ใส่ค่าใน `js/config.js` แอปจะเปิดใน **โหมดตัวอย่าง** ใช้ข้อมูลจำลอง มีเมนู "ดูในฐานะ" ให้สลับผู้ใช้เพื่อดูว่าแต่ละบทบาทเห็นอะไร (รีเฟรชแล้วข้อมูลกลับเป็นค่าเริ่มต้น)

เปิดบนเครื่องตัวเอง:

```bash
# ในโฟลเดอร์โปรเจกต์
python3 -m http.server 8080
# แล้วเปิด http://localhost:8080
```

> ต้องเปิดผ่าน web server (เปิดไฟล์ `index.html` ตรง ๆ ด้วยการดับเบิลคลิกจะไม่ทำงาน)

## ติดตั้งใช้งานจริง

### 1) สร้างโปรเจกต์ Supabase

1. สมัคร/เข้าสู่ระบบที่ supabase.com แล้วกด **New project** (เลือก Region: Southeast Asia (Singapore))
2. ไปที่ **SQL Editor > New query** วางเนื้อหาไฟล์ `supabase/schema.sql` ทั้งไฟล์ แล้วกด **Run**
   - ไฟล์นี้จำกัดให้ล็อกอินได้เฉพาะอีเมล `@megaclinicthailand.com` ถ้าต้องการเปลี่ยน ให้แก้ค่า `v_domain` ก่อนรัน
3. ไปที่ **Project Settings > API** คัดลอก **Project URL** และ **anon public key**

### 2) ตั้งค่าการล็อกอิน

**แบบที่แนะนำ: ล็อกอินด้วยบัญชี Microsoft 365 ของบริษัท** (ชื่อผู้รับของจะตรงกับชื่อใน Microsoft 365)

1. ให้ IT ลงทะเบียนแอปที่ Microsoft Entra admin center > **App registrations > New registration**
   - Supported account types: *Accounts in this organizational directory only*
   - Redirect URI (Web): `https://<project-ref>.supabase.co/auth/v1/callback`
2. สร้าง **Client secret** แล้วจด Application (client) ID, Directory (tenant) ID และ secret
3. ใน Supabase ไปที่ **Authentication > Providers > Azure** เปิดใช้งาน ใส่ Client ID, Secret และ Azure Tenant URL `https://login.microsoftonline.com/<tenant-id>`

**แบบง่าย: ลิงก์เข้าสู่ระบบทางอีเมล** ใช้ได้ทันทีโดยไม่ต้องตั้งค่าเพิ่ม (Supabase ส่งอีเมลให้) ถ้าไม่ใช้แบบใด ให้ปิดใน `js/config.js`

จากนั้นที่ **Authentication > URL Configuration** ใส่ Site URL และ Redirect URLs เป็นที่อยู่ GitHub Pages ของคุณ เช่น `https://<github-user>.github.io/<repo>/`

### 3) ใส่ค่าในแอป

แก้ไฟล์ `js/config.js`

```js
SUPABASE_URL: 'https://xxxx.supabase.co',
SUPABASE_ANON_KEY: 'eyJhbGciOi...',
```

anon key เป็นคีย์สาธารณะ ใส่ในหน้าเว็บได้ (ห้ามใส่ `service_role` key เด็ดขาด)

### 4) ขึ้น GitHub Pages

1. สร้าง repository แบบ **Public** บน GitHub
2. ในหน้า repo กด **Add file > Upload files** แล้วลากไฟล์และโฟลเดอร์**ข้างใน**โฟลเดอร์ `mega-receiving` ทั้งหมด (รวมโฟลเดอร์ `.github`) ไปวาง แล้วกด **Commit changes**
3. ไปที่ **Settings > Pages** ช่อง Source เลือก **Deploy from a branch** เลือก Branch `main` และโฟลเดอร์ `/ (root)` แล้วกด Save
4. รอ 1–2 นาที เว็บจะอยู่ที่ `https://<github-user>.github.io/<repo>/`
5. ครั้งต่อไปที่แก้ไฟล์ อัปโหลดทับแล้วเว็บจะอัปเดตเอง

### 5) ตั้งผู้ดูแลระบบคนแรก

1. เปิดเว็บแล้วล็อกอินด้วยบัญชีของคุณ 1 ครั้ง
2. กลับไปที่ Supabase SQL Editor รันคำสั่ง (แก้อีเมล):

```sql
update public.profiles
  set role = 'admin', scope = 'all', can_export = true, can_verify = true, can_manage = true
  where email = 'your.name@megaclinicthailand.com';
```

3. รีเฟรชเว็บ จะเห็นเมนู **จัดการสิทธิ์** จากนั้นกำหนดสิทธิ์คนอื่นผ่านหน้าเว็บได้เลย

## ลบรูปเก่าอัตโนมัติ (เก็บ 60 วัน)

ทุกวันเวลา 03:00 น. GitHub Actions จะลบ**รูปสินค้า**ที่อัปโหลดมานานกว่า 60 วัน ข้อมูลใบรับของ (รายการ จำนวน ผู้รับ วันที่ สาขา สถานะ) ยังอยู่ครบ ในหน้าเว็บจะขึ้นว่า "ลบแล้ว (เกิน 60 วัน)" แทนรูป ค่าเริ่มต้นจะ**ไม่ลบไฟล์เอกสาร** (ใบกำกับภาษี / ใบส่งของ)

ตั้งค่าครั้งเดียวที่ repo บน GitHub > **Settings > Secrets and variables > Actions**

| ชนิด | ชื่อ | ค่า |
|---|---|---|
| Secret | `SUPABASE_URL` | Project URL ของ Supabase |
| Secret | `SUPABASE_SERVICE_ROLE_KEY` | service_role key (Supabase > Project Settings > API) ใส่ที่นี่เท่านั้น ห้ามใส่ในโค้ด |
| Variable (ไม่บังคับ) | `RETENTION_DAYS` | จำนวนวันที่เก็บ ค่าเริ่มต้น 60 |
| Variable (ไม่บังคับ) | `PURGE_KINDS` | `photo` (ค่าเริ่มต้น) หรือ `photo,document` ถ้าต้องการลบรูปเอกสารด้วย |

ทดลองดูก่อนว่าจะลบอะไร: แท็บ **Actions > ลบรูปเก่ากว่า 60 วัน > Run workflow** ใส่ `1` ในช่องทดลอง

ถ้าเปลี่ยนจำนวนวัน ให้แก้ `PHOTO_RETENTION_DAYS` ใน `js/config.js` ให้ตรงกันด้วย (ใช้แสดงข้อความในหน้าเว็บ)

> GitHub จะหยุดงานตั้งเวลาอัตโนมัติ ถ้า repo สาธารณะไม่มีการแก้ไขเลย 60 วัน (มีอีเมลเตือนก่อน) กดเปิดใหม่ได้ที่แท็บ Actions

## โครงสร้างไฟล์

```
index.html              หน้าเว็บหลัก
css/styles.css          หน้าตา (รองรับโหมดมืด)
js/config.js            ค่าเชื่อมต่อ Supabase
js/constants.js         สาขา ประเภทเอกสาร บทบาท และกติกาการมองเห็น
js/app.js               หน้าจอและการทำงานทั้งหมด
js/api-demo.js          ข้อมูลจำลองสำหรับโหมดตัวอย่าง
js/api-supabase.js      เชื่อมต่อ Supabase
supabase/schema.sql     ตาราง สิทธิ์ (RLS) และที่เก็บไฟล์
.github/workflows/purge-photos.yml   ลบรูปเก่ากว่า 60 วัน ทุกวัน
scripts/purge-old-photos.mjs   สคริปต์ลบรูป
```

ไม่ต้อง build ไม่ต้องติดตั้ง Node.js แก้ไฟล์แล้ว push ได้เลย

### เพิ่ม/เปลี่ยนสาขา

แก้ 2 ที่ให้ตรงกัน: `BRANCHES` ใน `js/constants.js` และ `check (branch in (...))` ในตาราง `receipts` (รัน `alter table` ใน Supabase)

## หมายเหตุ

- รูปถูกย่อเหลือด้านยาวไม่เกิน 1600 px ก่อนอัปโหลด เพื่อประหยัดพื้นที่ (ตั้งค่าได้ที่ `MAX_IMAGE_SIZE`)
- ผู้รับของแก้ไขรายการของตัวเองได้ภายใน 24 ชั่วโมง ถ้ายังไม่ถูกจัดซื้อตรวจ (ฐานข้อมูลรองรับแล้ว หน้าจอแก้ไขยังไม่ได้ทำ)
- ไม่มีการลบใบรับของจากหน้าเว็บ เพื่อเก็บประวัติให้ครบ
